## What the branch is supposed to do
- **Rectangle layout.** The team moved the four seat force sensors (FlexiForce A502, each through a transimpedance amp) from a plus layout to a rectangle, one sensor per corner. The branch adds centre-of-pressure (CoP) lean math for that layout, in plate inches, with per-rider calibration:
  - the rider sets neutral by sitting in *active neutral*;
  - the rider sets a full-lean distance for each of the four directions;
  - each direction has a deadzone.
- **Plus layout.** The old plus-layout math must stay available behind a runtime setting and behave exactly as before.
- **Hardware facts:**
  - Channel → corner: R = front-right, L = front-left, F = back-left, B = back-right.
  - Corner positions in inches from the old plus centre (x right, y forward): FL (−5.75, +3.0), FR (+5.375, +2.9375), BL (−5.75, −4.1875), BR (+5.3125, −4.25).
  - Raw zero force ≈ 372 counts. The empty plate reads ≈ 391/406/427/400 on F/B/L/R.
- **Odd tuned constants in this code are deliberate.** Flag a change to one only if it's wrong.

# Review of `charles/corner-cop`

**Score: 8/10 for a wheels-off bench test. Do not put a rider on it until findings 1 and 2 are closed.**

The math is right, the gating holds, and everything builds and passes. The weak spot is a seat sensor channel that dies without reaching the ADC rail.

## Findings, most severe first

### 1. A dead sensor channel drives the chair, and nothing trips
[LeanDriveMode.cpp:13](<worktree>/wheelchair-firmware/src/driveModes/LeanDriveMode.cpp:13), [lean_layout.cpp:12](<worktree>/wheelchair-firmware/src/driveModes/lean_layout.cpp:12)

- **Scenario:** calibrated at E9 active neutral (1038/864/657/790), rider sitting still, one channel drops to anywhere from 101 to about 390 counts.
- **Why nothing trips:** the rail disarm only fires at ≤100, `cornerForces` floors the channel to zero force, and the seat gate still reads seated.
- **Measured through the real `LeanDriveMode` on host:**

| Dead channel (at 372) | Left wheel | Right wheel | Seated | Railed |
|---|---|---|---|---|
| F (back-left) | +1.00 | −0.21 | 1 | 0 |
| B (back-right) | −0.35 | +0.83 | 1 | 0 |
| L (front-left) | −0.005 | −0.28 | 1 | 0 |
| R (front-right) | +0.22 | −1.00 | 1 | 0 |
| F and B together | +1.00 | +0.02 | 1 | 0 |
| L and R together | −1.00 | −1.00 | 1 | 0 |

- **Not a regression in kind:** the plus math also runs away on this fault (by my arithmetic, full reverse; I did not run it). The corner path is new code, though.
- **Unknown:** I don't know what a pulled wire actually reads. If it lands at ≤100, the existing rail disarm catches it within a tick. If the amplifier idles at its 372 offset, nothing catches it.
- **Suggested fix:**
  1. On the bench, unplug each sensor in turn and read `DBG R`.
  2. Raise `SENSOR_RAIL_LOW` from 100 to about 340. The lowest reading in the whole E9 log is 366, so 101–365 is impossible for a healthy channel.
  3. If a pulled wire reads about 372, add a corner-layout plausibility stop, for example a CoP jump of inches in one tick. Total load alone is too close to call: one dead channel leaves 62% of neutral load, and the healthy E9 sweep dipped to 72%.

### 2. Old saved profiles inherit corner settings from whichever profile was active before
[Protocol.cpp:149](<worktree>/wheelchair-firmware/src/config/Protocol.cpp:149)

- **Cause:** `selectProfile` applies only the records a profile contains. Any profile saved before this branch lacks the 17 new fields.
- **Reproduced on host:**
  - Boot, then old profile: defaults (CORNER, reach 2.0).
  - Switch to a new profile set to PLUS, reach 5.5, deadzone 0, empty-plate F 900, gain B 7.
  - Switch back to the old profile: still PLUS / 5.5 / 0 / 900 / 7.
- **Consequence:** the same knob position behaves differently depending on history. Worst case is plus math on rectangle hardware. It is not a runaway, because every LEAN entry forces recalibration.
- **Suggested fix:** reset fields absent from the payload to defaults before `applyTlvs` (keeping the validate rollback), or re-save every profile after flashing. Add a test; none covers this.

### 3. One shared deadzone, and relaxing creeps forward at 14%
[lean_layout.h:85](<worktree>/wheelchair-firmware/src/driveModes/lean_layout.h:85), [DriveSettings.cpp:89](<worktree>/wheelchair-firmware/src/config/DriveSettings.cpp:89)

- **Spec gap:** the brief says each direction has a deadzone. The branch has a single `cornerDeadzone` for all four, capped at 0.5".
- **Scenario:** E9 passive neutral sits 0.74" forward of active neutral. A rider who calibrates in active neutral and then relaxes gets +0.14 speed. The author's own test asserts this at `corner_layout_test.cpp:196`.
- **Suggested fix:** per-direction deadzones, so forward can absorb the slump without dulling turns. Three more floats need 24 bytes, and the Teensy has 23 free, so something has to give. Otherwise, decide explicitly that the creep is acceptable.

### 4. `MinReach` of 0.6" accepts a calibration that turns a slump into full speed
[lean_layout.h:90](<worktree>/wheelchair-firmware/src/driveModes/lean_layout.h:90), [LeanDriveMode.cpp:290](<worktree>/wheelchair-firmware/src/driveModes/LeanDriveMode.cpp:290)

- **Scenario:** a lazy hold-calibration of 0.6" each way is accepted. The same 0.74" slump then maps to (0.74 − 0.25) / (0.6 − 0.25), which clamps to full forward. This is arithmetic, not a run.
- **Suggested fix:** reject reach below about 1.2". The E9 holds were 1.6–2.06".

### 5. A hold-calibrated reach silently outlives riders and overrides dashboard edits
[LeanDriveMode.cpp:40](<worktree>/wheelchair-firmware/src/driveModes/LeanDriveMode.cpp:40)

- **Scenario A:** after any successful hold-calibration, setting "Full lean forward" to 4.0 in the dashboard returns OK and changes nothing until a reboot or profile change.
- **Scenario B:** the next rider's short press inherits the previous rider's reach. `building-with-charles.md` says the configured reach applies.
- **Only tell:** the `*` in `DBG SENSORS`.
- **Suggested fix:** clear `reachCalibrated` when a reach setting changes, and decide whether a short press should keep it.

### 6. The once-a-second telemetry burst no longer fits the Bluetooth buffer
[main.cpp:499](<worktree>/wheelchair-firmware/src/main.cpp:499), [LeanDriveMode.cpp:344](<worktree>/wheelchair-firmware/src/driveModes/LeanDriveMode.cpp:344)

- **Numbers:** the 1 Hz lines total 436 bytes and the 20 Hz lines 183, so 619 against 576 of room. Before the branch it was 490.
- **Scenario:** when the two ticks land within about 4 ms of each other, a whole line is dropped every second. The CSV row is written last, so it goes first.
- **Status:** arithmetic from E9 line lengths, not observed on hardware.
- **Suggested fix:** grow the added TX buffer to 1024.
