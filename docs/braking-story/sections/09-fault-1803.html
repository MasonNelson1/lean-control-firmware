Problem 1, second time

The 18:03 fault: turning while slowing

By 18:03 the clamp had been changed so it only limits the chair's average speed, which let the rider steer while braking. Here the rider is slowing from about 3.3 m/s and turning. To turn, the inside (left) wheel's setpoint drops below the outside wheel's. It goes all the way to −3 to −5 RPM: slightly backwards, while the left wheel is still rolling forward at about 63 RPM (2 m/s).

A setpoint of −5 RPM is inside the VESC's "stop" band, so it's the same duty-zero brake as 17:08, with the same result. The left motor current reaches about −20 A in the 50 ms samples, the left VESC trips at 49 A and lets go for 0.6 s, and only the right wheel is braking.

After this fault the firmware got a "no plugging" rule: a wheel rolling faster than 15 RPM is never commanded backwards; it's commanded to 0 instead. That removes the reverse command, but 0 RPM is still inside the VESC's stop band. So the no-plug rule sends the wheel into the same duty-zero brake that tripped at 17:08. It makes this fault less likely, but it doesn't remove it. The real fix is the same for both: never hand the VESC a near-zero setpoint while the wheel is rolling.
